Genomics skills, in your editor

ClawBio speaks MCP, so the skill library is callable from Cursor, Zed, VS Code agent mode and Claude Desktop, not just Claude Code. Most bioinformatics MCP servers retrieve records. This one executes: it runs the real skill on your machine and hands back the report, the structured result, and a commands.sh with SHA-256 checksums, so the analysis can be replayed without the agent that produced it.

$ uvx --from 'clawbio[mcp]' clawbio mcp

No install required. Add the same three lines to your client's config and restart it.

  • ✅ 95 skills, each flagged runnable or spec-only
  • 🔒 Demo data only until you opt in explicitly
  • 🏠 Local stdio. No hosted endpoint, by design
// Cursor, Claude Desktop, VS Code, Zed
{
  "mcpServers": {
    "clawbio": {
      "command": "uvx",
      "args": ["--from", "clawbio[mcp]",
               "clawbio", "mcp"]
    }
  }
}

The Problem
Reproducing bioinformatics analyses is broken
# Without ClawBio
$ git clone repo && cd repo
# Wrong Python version...
# Reference data link is dead...
# Paths hardcoded to /home/jsmith/data/
# Email first author. Wait 3 weeks.
# Give up.
  • ✗ Dependency hell & broken environments
  • ✗ Dead links to reference data
  • ✗ Hardcoded paths & missing configs
  • ✗ AI hallucinates star alleles & outdated guidelines
  • ✗ No audit trail, no checksums
# With ClawBio
$ python skills/multiqc-reporter/multiqc_reporter.py --demo --output /tmp/multiqc_demo

✓ Demo report regenerated.
✓ Replay command saved alongside outputs.
✓ Checksums available for verification.

# Or with natural language:
$ openclaw "Profile my pharmacogenes"

Many skills write a reproducibility/ bundle with replay commands, environment metadata, and output checksums. Exact files vary by skill, and some replays still require local tools or original inputs.

Why ClawBio
Domain expertise, frozen into code

ChatGPT and Claude are smart generalists. ClawBio skills are domain experts' proven pipelines — executed correctly every time.

🏠
Local-first by default
Your genome is analysed on your machine. Skills that transmit data to external services are clearly labelled and run only when you invoke them.
🔁
Reproducible

Modular

Recent Updates
Latest from the community
🧪
CI: automatically run the tests of any skill a PR touches. The CI pipeline now detects which skills are modified by a pull request and runs their test suites automatically. Skill contributors no longer need to manually trigger tests; failures surface before review. Keeps the full test suite (currently 4,280 tests) green on every merge.
PR #330 · merged · 1 August 2026
🧬
New skill: just-prs — evidence-aware polygenic risk scoring from a local VCF or WGS callset via a stdio MCP bridge. Scores multiple PRS models (curated, full GWAS, meta), applies ancestry-matched LD pruning, and returns a consensus estimate with a per-variant evidence table. Contributed by @antonkulaga. Total: 95 skills.
PR #324 · merged · 1 August 2026
🐛
Fix: pharmgx-reporter reference positions corrected for GRCh38. Three PharmGx loci were mapped to GRCh37 coordinates instead of GRCh38, causing missed variant calls for users processing GRCh38-aligned genome files. All 31 SNP positions now validated against GRCh38, unblocking GRCh38 input for the pharmacogenomics reporter.
PR #325 · merged · 1 August 2026
🔌
MCP server launched: all 95 skills callable from Cursor, Zed, VS Code, and Claude Desktop. Adds the ClawBio MCP server (clawbio mcp) so the entire skill library is accessible via the Model Context Protocol. Skills default to demo data only until you opt in, keeping your genome local. Also corrects public skill counts in the catalog and documentation to 95 total skills.
PR #326 · merged · 29 July 2026
🔒
clinical-variant-reporter: fail-closed self-audit with hard-abstain. Adds a self-audit layer that forces a hard abstain whenever the reporter cannot meet its own confidence threshold. The skill refuses to return a verdict rather than emitting a low-confidence call, improving safety for secondary findings in clinical contexts.
PR #323 · merged · 21 July 2026
🐛
Fix: clinical-variant-reporter crash when VEP returns clin_sig_allele as a string. Resolves a crash when the VEP REST API returns clin_sig_allele as a plain string instead of a list. The parser now handles both types defensively.
PR #322 · merged · 21 July 2026
⚙️
Improvement: skill listing with section headings and total count. The clawbio list command now groups skills by maturity tier with labelled section headings and prints a total count. Improves agent skill-discovery ergonomics and makes it easier to see which skills are production-ready at a glance. Contributed by @sahandtkod-byte.
PR #321 · merged · 21 July 2026
⚙️
Fix: deterministic skills catalogue generation. Sorts rglob output in generate_catalog.py so skills/catalog.json is byte-identical across Linux, macOS, and Windows regardless of filesystem ordering. Prevents spurious diffs in version control after regeneration. Contributed by @sahandtkod-byte.
PR #319 · merged · 20 July 2026
⚙️
Fix: CLI now correctly lists agent-readable skills. Resolves a bug in the clawbio list command where skills were silently filtered before the agent routing layer, causing valid skills to be omitted from skill-discovery queries. Contributed by @Sanjays2402.

nf-core wrappers: seven replay and portability defects resolved. Hardens all three nf-core wrappers (scrnaseq 4.1.0, sarek 3.8.1, rnaseq 3.26.0) after end-to-end replay testing. Get started in 30 seconds

Install with pip, conda, as a Claude Code plugin, or as an MCP server in any AI editor. Every skill includes demo data.

# Option 1: pip (recommended)
pip install clawbio
clawbio run pharmgx --demo

# Option 2: conda
conda install -c bioconda clawbio

# Option 3: Claude Code plugin
/plugin marketplace add ClawBio/ClawBio
/plugin install clawbio

# Option 4: MCP server (Cursor, Zed, VS Code, Claude Desktop)
uvx --from 'clawbio[mcp]' clawbio mcp
